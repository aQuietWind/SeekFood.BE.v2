# Employee（员工管理）

> 端口：10003 | 服务名：employee

## 1. 这个模块是干什么的？

Employee 模块负责管理**商家的员工**。一个外卖商家（比如一家餐厅）通常不止老板一个人，还有厨师、服务员、外卖打包员等等。这个模块就是帮商家记录这些员工的信息，包括姓名、职位、部门、薪资、照片，以及员工的任职状态（在职还是离职）。

你可以把它理解成一个"员工花名册"，商家可以随时查看自己有哪些员工、谁在哪个部门、谁已经离职了。

## 2. 员工和商家的关系

一个商家可以有多个员工，但一个员工只能属于一个商家。这个关系在数据库里是通过 `merchant_id` 字段来维系的。

**数据隔离是怎么做的？** 这是一个很重要的设计点。每次操作员工数据时，系统会先从请求的 Token 里解析出当前登录的商家 ID（`merchantId`），然后所有 SQL 查询都带上这个 `merchantId` 作为条件。比如查询员工列表时，SQL 是 `SELECT ... WHERE merchant_id = ? AND is_delete = 0`，这样商家 A 永远看不到商家 B 的员工。

这个商家 ID 是从哪里来的呢？网关在验证 Token 的时候，会把用户 ID 塞到请求头里，然后 Employee 服务通过 `TokenIdContext`（一个 ThreadLocal 工具）取出来，再根据 ID 的号段规则判断出这是商家身份。

**员工离职不是真删除。** 数据库里有一个 `is_resign` 字段，离职时把这个字段设为 `true`，而不是把记录删掉。还有一个 `is_delete` 字段用于软删除，删除员工时也只是打个标记。这样做的好处是数据可追溯，以后要查历史记录时不会丢数据。

## 3. 员工的增删改查流程

整个流程的核心设计思路是：**先校验身份，再检查冷却期，然后操作数据，最后清理缓存。**

**新增员工：**
1. 从 Token 里拿到商家 ID
2. 检查冷却期（同一个商家 5 秒内不能重复新增员工，防止手抖点多了）
3. 用 Redis 自增生成一个全局唯一的员工 ID
4. 把员工数据写入 MySQL
5. 发一条 MQ 消息通知其他服务（比如"员工数量变了"）
6. 返回成功

**查询员工详情：**
1. 先查 Caffeine 本地缓存（最快，在 JVM 内存里）
2. 没命中就查 Redis（第二快，走网络但比 MySQL 快）
3. 再没命中就查 MySQL，查完之后回填到 Redis 和 Caffeine
4. 下次再查就直接从缓存拿了

这个"三级缓存"的设计（Caffeine -> Redis -> MySQL）是性能优化的关键。员工信息不会频繁变动，适合用缓存加速。

**更新员工照片：**
1. 保存新照片到本地磁盘
2. 更新数据库里的照片地址
3. 发一条 MQ 消息，异步删除旧照片文件
4. 为什么异步删除？因为文件 I/O 很慢，如果同步删除会拖慢接口响应速度。把删除任务丢给 MQ，让消费者慢慢处理就好。

**删除员工：**
1. 检查冷却期（6 秒内不能重复删除）
2. 把 `is_delete` 设为 `true`（软删除）
3. 清除 Caffeine 和 Redis 缓存
4. 发 MQ 消息通知数量变更

## 4. 亮点和坑

**亮点：**

- **三级缓存（Caffeine + Redis + MySQL）**：员工详情查询非常快，热点数据在本地内存，微秒级响应。
- **冷却期防重复操作**：新增、修改、删除都有冷却期，防止用户手抖或脚本恶意刷接口。
- **文件异步删除**：更新照片时，旧照片的删除不阻塞主流程，通过 MQ 异步处理。如果 MQ 消费失败，还会把失败的文件路径写入 Redis Stream，由定时任务每 5 秒重试一次。
- **软删除机制**：数据不会真的被删掉，只是标记一下，方便追溯。

**需要注意的坑：**

- **缓存一致性**：更新或删除员工信息后，需要手动清除缓存（`updateAndRemoveCaffeine`），否则用户看到的还是旧数据。这个模块用的是"更新即删除"策略，而不是"更新即刷新"，因为删除缓存比更新缓存更简单可靠。
- **文件存储是本地路径**：照片存在服务器本地磁盘上。如果部署了多个实例，实例 A 存的照片实例 B 读不到。生产环境应该换成对象存储（MinIO、阿里云 OSS 等）。
- **MQ 消息没有做幂等**：如果"员工数量变更"消息被重复消费，统计数据可能不准。不过这个场景对精度要求不高，影响不大。

## 5. 快速启动

**需要先装好的东西：**
- JDK 21
- MySQL 8.0+（执行 `MysqlCreate.sql` 建表，数据库名 `seek_food_employee`）
- Redis 7.0+（缓存、冷却期、ID 生成器）
- RabbitMQ 3.12+（文件异步删除、数量变更通知）
- Nacos 2.4+（配置中心）

**启动步骤：**
1. 导入 Nacos 配置（`employee-self-dev.yaml` 等）
2. 执行 `MysqlCreate.sql` 创建表
3. 确保 Redis、RabbitMQ、Nacos 在运行
4. 启动 `EmployeeApplication`，端口 10003

**依赖的模块：** Config、Util、DTO

**对外接口：** 提供 `/employee/insert`、`/employee/detail`、`/employee/message`、`/employee/image`、`/employee/resign`、`/employee/delete` 等 REST API。
