# Admin（管理后台）

> 端口：10013 | 服务名：admin

## 1. 这个模块是干什么的？

Admin 模块是平台的**管理后台服务**。它不像 User 模块那样面向普通用户，也不像 Merchant 模块那样面向商家，它是给**平台管理员**用的。

管理员能做什么呢？主要有三件事：**登录后台、处理用户建议、查看平台数据**。这个模块是整个平台的"运营中枢"，虽然功能不多，但安全设计上一点都不能马虎。

## 2. 管理员能做什么？

**登录：** 管理员通过用户名和密码登录。用户名和密码不是存在数据库里的，而是配在 Nacos 配置中心。这样即使数据库被拖库了，管理员密码也不会泄露。登录成功后，系统生成一个 JWT Token，存在 Redis 里，同时通过 HttpOnly Cookie 返回给浏览器。为什么用 HttpOnly Cookie？因为前端 JavaScript 读不到它，XSS 攻击偷不走 Token。

**处理用户建议：** 用户可以在 App 里提交反馈建议（比如"希望增加夜间模式"），管理员登录后台后可以看到这些建议列表，然后一个个确认处理。确认之后，建议附带的图片会被异步删除，节省磁盘空间。

**平台统计：** 管理员可以查看平台运营数据，比如注册用户数、订单量等。这个功能目前比较基础，但架构上已经预留了扩展空间。

## 3. 建议管理流程

建议管理是 Admin 模块最核心的业务流程，分为三个阶段：

**发布建议：** 用户在前端提交建议，可以附带文字描述和一张图片。Admin 服务收到请求后，先检查冷却期（防止用户疯狂提交），然后生成一个全局唯一的建议 ID，把图片保存到本地磁盘，最后把建议信息写入 MySQL 的 `suggestion` 表。如果图片保存失败但数据库写入成功了，系统会发一条 MQ 消息把刚保存的图片删掉，保证数据一致性。

**查看建议列表：** 管理员登录后，可以分页查看所有未确认的建议。这个查询加了 Caffeine 缓存，因为管理员可能会频繁刷新列表。

**确认建议：** 管理员点"已处理"后，系统把 `is_ack` 字段设为 `true`。然后触发异步文件删除：发一条 MQ 消息，消费者收到后去删除建议附带的图片文件。如果删除失败（比如文件被其他进程占用了），消费者会把文件路径写入 Redis Stream，由定时任务每 5 秒重试一次。

这个流程的设计思路是：**主流程只做最必要的事（更新数据库状态），慢操作（删除文件）全部异步化**。用户点"确认"后立刻看到成功，文件什么时候删完用户不关心。

## 4. 亮点和坑

**亮点：**

- **管理员账号不存数据库**：用户名和密码配在 Nacos，安全性更高。即使数据库被拖库，也无法获取管理员凭证。
- **HttpOnly Cookie 防 XSS**：Token 放在 Cookie 里，前端 JavaScript 读不到，减少了 Token 被窃取的风险。
- **冷却期防暴力破解**：登录接口有冷却期，防止攻击者用脚本暴力尝试密码。
- **文件异步删除 + 定时补偿**：双层保障，即使 MQ 消费失败，定时任务也会兜底。

**需要注意的坑：**

- **管理员账号是单点的**：Nacos 配置里只有一个用户名密码，不支持多管理员。如果需要多管理员，需要改成数据库存储。
- **建议列表没有分页缓存**：目前只是简单的 Caffeine 缓存，没有做分页缓存优化。如果建议量很大，需要考虑更好的缓存策略。
- **文件存储是本地路径**：和 Employee 模块一样的问题，多实例部署时需要换成对象存储。

## 5. 快速启动

**需要先装好的东西：**
- JDK 21
- MySQL 8.0+（执行 `MysqlCreate.sql` 建表，数据库名 `seek_food_admin`）
- Redis 7.0+（Token 存储、冷却期、ID 生成器）
- RabbitMQ 3.12+（文件异步删除）
- Nacos 2.4+（配置中心，记得在 `admin-self-dev.yaml` 里配置管理员用户名密码）

**启动步骤：**
1. 导入 Nacos 配置（`admin-self-dev.yaml` 等）
2. 执行 `MysqlCreate.sql` 创建 `suggestion` 表
3. 确保 Redis、RabbitMQ、Nacos 在运行
4. 启动 `AdminApplication`，端口 10013

**依赖的模块：** Config、Util、DTO
