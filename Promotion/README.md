# Promotion（营销活动）

> 端口：10007 | 服务名：promotion

## 1. 这个模块是干什么的？

简单说，**营销活动模块就是帮商家搞活动的**。商家想吸引用户，要么搞个"登录就送券"的活动，要么搞个"限量抢券"的活动。这个模块负责管理这两种活动的创建、发布、查询，以及最重要的——**用户领券**。

你可以把它想象成商家的"营销工具箱"：创建一个活动，设定好时间、关联一张优惠券，然后用户就可以通过活动页面来领券了。

## 2. 两种活动有什么区别？

这个模块支持两种活动，它们的区别不仅仅是名字不同，设计思路也完全不同：

**登录即得活动（Login Promotion）**：用户登录就能领，没有数量限制。这种活动适合"拉新促活"，比如新店开张，想让更多人知道，就发一张"新用户专享券"，谁来都能领。数据库里只有一个 `participant_amount`（参与人数）来统计，没有库存上限。

**限时抢券活动（Grab Promotion）**：和秒杀一个道理，券的数量是有限的。比如"前100名用户领10元券"，这里有一个 `voucher_origin_amount`（原始数量）和一个 `voucher_now_amount`（剩余数量），每领一张就减一。这就带来了一个经典问题：**怎么防止超卖？**

## 3. 抢券流程（怎么防止超卖？）

这是整个模块最有意思的地方。假设你是一个商家，发布了一个"限量100张"的抢券活动，同一时间有1000个用户来抢，你怎么保证不会发出去第101张？

这个模块的抢券流程是这样的：

**第一步，先加锁。** 用户来领券时，系统先用 Redisson 分布式锁锁住这个活动。锁的 key 是 `promotionId`，也就是说不同活动之间互不影响，但同一个活动同一时间只能有一个人操作。为什么要用分布式锁？因为这个服务可能部署了多个实例，普通的 JVM 锁（synchronized）管不了跨实例的情况。

**第二步，再检查。** 拿到锁之后，先通过 Feign 调用优惠券服务（Voucher），看看这个用户是不是已经领过了。如果领过了，直接返回"你已经领过了"，释放锁。

**第三步，扣库存。** 如果没领过，就执行 MySQL 的 UPDATE 语句，把 `voucher_now_amount` 减一。这里的关键是，SQL 语句带了一个条件：`WHERE voucher_now_amount > 0`。如果库存已经没了，UPDATE 的影响行数就是 0，代码就知道"抢光了"。

**第四步，最后发消息。** 扣库存成功后，发一条 MQ 消息给优惠券服务，告诉它"这个用户领了这张券，请记录一下"。为什么要用 MQ 而不是直接调 Feign？因为记录持有关系这件事不着急，用户可以立刻看到"领券成功"，后台慢慢记录就好。这就是异步削峰。

**最后，释放锁。** 不管成功还是失败，锁都要在 `finally` 块里释放，防止死锁。

整个流程走下来，分布式锁保证了"同一时间只有一个人扣库存"，SQL 的 WHERE 条件保证了"库存不会变成负数"。这就是防止超卖的核心思路。

## 4. 亮点和坑

**亮点：**

- **Redisson 分布式锁用得精细**：锁的粒度是单个活动，不是全局锁。活动 A 和活动 B 的抢券互不影响。
- **Caffeine 本地缓存加速**：活动详情是高频读取的数据，放在 JVM 内存里，查询速度在微秒级别。缓存过期时间通过 Nacos 配置，改配置不用重启。
- **MQ 异步削峰**：领券后立刻返回成功，记录持有关系的事情交给 MQ 慢慢处理，不会让用户干等。
- **冷却期防刷**：创建活动、抢券等操作都有 Redis 冷却期（比如 6 秒内不能重复创建活动），防止脚本恶意刷接口。

**需要注意的坑：**

- **锁的获取方式是 tryLock 非阻塞**，拿不到锁直接返回"操作频繁"，不会排队等待。这个设计在高并发下是合理的，但如果你期望用户排队等待，那需要改成阻塞式获取。
- **MQ 消息没有做幂等校验**。如果 MQ 因为网络问题重复投递了同一条消息，可能会导致优惠券服务重复记录持有关系。生产环境建议加上"消息 ID + Redis 判重"。
- **Feign 调用优惠券服务时没有降级方案**。如果优惠券服务挂了，领券就会直接报错。更好的做法是给 Feign 客户端配一个 fallback。

## 5. 快速启动

**需要先装好的东西：**
- JDK 21
- MySQL 8.0+（执行 `MysqlCreate.sql` 建表）
- Redis 7.0+（分布式锁和冷却期要用）
- RabbitMQ 3.12+（异步通知优惠券服务）
- Nacos 2.4+（配置中心）

**启动步骤：**
1. 先把 `NacosConfig/` 目录下的配置文件导入 Nacos 控制台
2. 执行 `MysqlCreate.sql` 创建数据库和表
3. 启动 Redis、RabbitMQ、Nacos
4. 运行 `PromotionApplication`
5. 服务启动在 `10007` 端口

**依赖的模块：** Config（配置绑定）、Util（工具类）、DTO（数据对象）

**依赖的外部服务：** Voucher（优惠券服务，通过 Feign 调用）
